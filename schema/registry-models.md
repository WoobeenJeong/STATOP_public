# STATOP 모델링 검증 목록 (registry-models) — 1.0.0

- 연계: `stat-validator-rfp-1.0.0.md` 모듈 B, `registry-errors.md`(회귀 T-8xx·범주 오류), `registry-guardrails.md`(SRM·누수·불균형), `registry-scores.md`(분류·보정 지표), `registry-metric-roles.md`(Goal/Support/Guardrail)
- 상태: 검토용 초안. 별도 지시 전까지 덮어쓴다
- **성격(중요)**: STATOP는 모델을 **학습시키지 않는다.** 학습 설정·데이터 구성·산출물(예측·로그·config)을 받아 **감사(audit)**만 한다. 학습 중 실시간 감시는 범위 밖(실험 추적 도구 영역).
- ID: `MB-Q`(질문) / `MB-M`(모델 티어) / `MB-C`(체크). 체크는 검정처럼 Gate/Diagnostic/Judgment 등급과 3색을 가짐

> v1 원칙: **모델 종류와 무관하게 걸리는 데이터·설정·평가 오류**를 먼저 완성한다. 팀 오류의 대부분(내부 #6/#10/#11)이 여기 속한다.
> **STATOP 는 모델을 돌리지 않는다.** 그래서 "어떤 모델이냐"가 아니라 "그 모델로 학습할 때 무엇을 확인해야 하느냐"를 말한다 — MLP 로 학습할 계획이면 fold 가 제대로 나뉘었는지, AUC 로 충분한지 PR-AUC 가 필요한지 같은 **방법론적 특이사항**을 준다. STATOP 자신이 도는 연산은 CPU 에서 가볍게 끝나는 것뿐이다 (학습곡선 로그를 받아야 판정되는 항목만 4.3 에 남겨 두었다).

### 3.6 모델×전처리 규칙 (MB-C10·MB-C11 의 감지 원천)

MB-C10 이 "모델×전처리 규칙"이라고 가리키던 표. **필요 여부는 모델이 값을 어떻게 쓰는지에서
나온다** — 거리·벌점은 척도에 직접 의존하고, 분할은 순서만 보므로 단조 변환에 불변이다.

| 계열 | 예 | 표준화 | 왜 |
|---|---|---|---|
| distance | kNN, SVM(RBF/선형), k-means | 필요 | 거리·커널이 척도에 직접 의존 |
| penalized | 로지스틱/선형 회귀 + L1·L2(ridge/lasso/elastic) | 필요 | 벌점이 계수 크기에 걸려 척도 큰 변수가 덜 벌점받음 |
| linear | 로지스틱/선형 회귀 (정규화 없음) | 불필요 | 계수가 척도를 흡수 — 값은 같고 해석 단위만 달라짐 |
| neural | MLP, CNN, RNN, Transformer | 조건부 | 입력 스케일이 고르지 않으면 수렴이 늦어질 수 있다. 다만 내부 구조·옵티마이저·입력 형태(tabular 여부 등)에 따라 달라 일률적으로 말할 수 없다 |
| projection | PCA, LDA, UMAP, t-SNE | 조건부 | 척도가 큰 변수가 축에 더 큰 영향을 줄 수 있다. 다만 **원척도 그대로 보는 것이 목적일 때도 있어** 목적에 따라 갈린다 |
| tree | decision tree, RF, GBM, XGBoost, LightGBM | 불필요 | 분할이 값의 순서만 보므로 단조 변환에 불변 |
| naive_bayes | GaussianNB, MultinomialNB | 불필요 | 변수마다 따로 적합하므로 서로의 척도가 영향을 주지 않음 |

- 계열 이름(코드)은 영어 소문자, 표시 이름은 `예` 열의 것을 쓴다.
- `불필요`는 "해도 된다"는 뜻이지 "하면 틀린다"가 아니다 — **막지 않고 필요 없다고만 말한다.**
- **`조건부`는 어느 쪽이 옳다고 말하지 않는다.** 목적·구조에 따라 갈리므로 **어느 쪽을
  택했는지 기록만 청한다.** 안 해도 되는데 해버리거나 그 반대여서 성적이 달라지는 일이
  생기지 않도록, 확정적인 어투를 쓰지 않는다.

### 3.7 모델 비교 규칙 (MB-C34 의 감지 원천 · )

여러 모델을 견주는 자리에서 **무엇으로 비교할 수 있는지**는 모델쌍의 관계가 정한다.
비교가 불가능한데 숫자를 나란히 놓으면 없는 우열이 생긴다.

| 조건 | 비교 가능 | 쓸 수 있는 것 | 왜 |
|---|---|---|---|
| same_n_nested | 가능 | 우도비검정(LRT), AIC, BIC | 한 모델의 항이 다른 모델 항의 부분집합이고 자료가 같다 |
| same_n_non_nested | 부분 | AIC, BIC | 포함관계가 아니라 LRT 의 귀무분포가 성립하지 않는다 |
| different_n | 주의 | 공통 행으로 다시 적합해 비교 | 결측 처리로 행 수가 달라 같은 자료를 본 것이 아니다 |
| different_outcome | 불가 | — | 결과변수가 다르면 우도의 단위가 달라 값을 견줄 수 없다 |
| different_family | 부분 | 예측성능(교차검증) | 분포족이 다르면 우도·AIC 를 직접 견줄 수 없다 |

- 판정은 **모델쌍마다** 낸다 — 어느 쌍이 왜 안 되는지 지목해야 고칠 수 있다 .
- `different_n` 은 **행 차이가 얼마나 되는지 함께 낸다** — 480 vs 478 과 480 vs 412 는
  다른 이야기다.
- `부분`은 "그 목록에 있는 것만 쓸 수 있다", `주의`는 "직접 견주기 전에 확인할 것이
  있다"는 뜻이다. 어느 쪽도 막지 않는다 ().

설정·데이터만 보면 되는 T1 항목(전처리 권고·비결정 고지 등)은 3절에 그대로 있다.

| 손실 이상(NaN·발산·정체) 고지 — 옛 MB-C33 | T1 | Diag, 학습 로그 필요 |
